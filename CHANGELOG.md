# Changelog

All notable changes to hydra-rpc are documented here.
Format follows [Keep a Changelog](https://keepachangelog.com/en/1.0.0/).

## [Unreleased]

## [1.1.0] - 2026-10-15

### Added

- Ed25519-signed update checksums: releases now also publish
  `hydra-rpc.sha256.sig`, a signature over the checksum file. The updater
  verifies it against `UPDATE_PUBLIC_KEYS` embedded in the running script and
  refuses any update whose signature is present but invalid (tampered release
  path). When no signature is published it falls back to checksum + syntax as
  before. Includes `scripts/sign_artifact.py`, `scripts/check_sig.py`,
  `make sign`, RFC 8032 test vectors (`tests/test_ed25519.py`), and a
  multi-key list to make future key rotation safe. The private key lives
  outside the repository (`~/.config/hydra-rpc/signing.key`).
- Offline-hermetic status contract test: `scripts/check_status_contract.py`
  now runs against a throwaway config/cache directory with a stub database, so
  CI needs no network and the check is fast and deterministic.

### Changed

- Updater verification ladder is now: Ed25519 signature (fail closed when
  published) → SHA256 checksum → Python syntax. `--check-update` exercises the
  same path as `--update`.

### Fixed

- `RPCClient.ping()` now treats oversized/malformed IPC frames as a dead
  connection (returns `False`, triggering reconnect) instead of letting the
  `ValueError` escape to the loop's generic error handler.

### Removed

- Dead `wineserver` entry from the default blocklist and example config:
  blocklist candidates must end in `.exe`, so it could never match.

## [1.0.1] - 2026-10-15

### Fixed

- `prune_sessions` no longer raises `TypeError` when a sessions cache mixes
  numeric and string `start_ms` values and exceeds the 256-entry cap
  (sort key now normalises with `int()`).
- `--validate-config` no longer double-prefixes "warning:" for an empty game
  database.

### Added

- README documents the exact `--status --json` field set and the stability
  policy (exact keys enforced by `scripts/check_status_contract.py` in CI).

## [1.0.0] - 2026-10-15

### Added

- Structured `--status --json` report (`version: 1`): timestamp, script path,
  `config_version`, `db` (url, cached_at, cached_age_seconds, entries), `socket`
  (found, path, attempts_tried, last_error), `detected` (with
  `matched_by: database|override|emulator`), `skipped` (with reasons), `notes`.
  Stdout stays pure JSON (diagnostics go to stderr).
- `config_version: 1` in config: legacy configs log a migration hint and missing
  keys use defaults; `ensure_config` writes it for new installs. Schema and
  example updated.
- DB cache diagnostics: fresh-cache age logged at debug level; download failures
  warn explicitly ("using stale cache from X ago with limited detection") and add
  a `notes` entry to the status report.
- Tolerant updater SHA256 check: verifies against `hydra-rpc.sha256` when
  published, refuses on mismatch, otherwise continues with syntax validation.
- Edge-case tests: `test_status_json.py`, `test_config_migration.py`,
  `test_updater_socket.py` (checksum + socket discovery), `test_db_cache.py`
  (fresh/expired/offline cache, `max_activities`). 73 tests total.
- `Makefile` with `install`, `install-user`, `uninstall`, `test`, `lint`, `check` targets.
- `config.example.json` with every supported setting and realistic override examples.
- `hydra-rpc.schema.json` (JSON Schema draft 2020-12) for editor validation of `config.json`.
- `hydra-rpc --status` one-shot diagnostic: prints a terminal table of detected
  processes and why each was or was not matched (matched / unknown / blocklisted /
  hydra-filtered / missing emulator app ID). `--status --json` emits structured
  versioned JSON for scripts and bug reports.
- Richer `--dry-run` output: now shows PID, application ID, and Hydra-marker source
  for each match instead of only exe + display name.
- Stronger config validation:
  - warns on unknown top-level config keys,
  - warns on malformed Discord application IDs (expected all-digit snowflakes),
  - warns when a configured `socket_path` does not exist,
  - `--validate-config` reports missing emulator app IDs and per-override ID problems.
- README: distro-specific install notes (Arch, Fedora, Ubuntu, Nix, Flatpak),
  copy-paste default paths section, "Known issues" section, "How to debug
  a missing game" flowchart, and launcher examples (Hydra, Heroic, Lutris,
  Bottles, Steam).

### Changed

- Source split into `src/` modules (`header`, `config`, `db`, `updater`, `ipc`,
  `detection`, `status`, `proc`, `main`); `./hydra-rpc` is now generated by
  `python3 build.py` and verified AST-identical (`build.py --check` in CI).
  Install and updater flows are unchanged (single-file artifact).
- `SCRIPT_VERSION = "1.0.0"`, included as `script.version` in status reports.

### Release process

- `make sha256` (re)generates the committed `hydra-rpc.sha256` the updater
  verifies against; CI fails if it is stale (`scripts/check_sha.py --check`).
- Tagging `vX.Y.Z` runs the release workflow (bundle check, tests, checksum,
  status contract) and publishes a GitHub Release with `hydra-rpc` +
  `hydra-rpc.sha256` assets.

### Fixed

- README config table: removed duplicated `refresh_unchanged_activities` row.
